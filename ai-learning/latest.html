今天最值得看：更强的 Agent，也需要更强的边界

过去 48 小时里，AI 产品的主线很清楚：OpenAI 推出更便宜的 GPT-6.1 Sol，并把“长期主动做事”的 dots Agent 推到前台；Anthropic 发布更快、更省的 Sonnet 5.5；NVIDIA 则把 Agent 安全从提示词层推进到沙箱和硬件监控。对开发者来说，2026 年的重点已经不是单纯“模型会不会回答”，而是模型能否稳定调用工具、持续执行，并且始终待在授权边界里。

1. OpenAI 正式推出 GPT-6.1 Sol

9 月 29 日 · OpenAI 官方模型文档 + Safety Hub

发生了什么：GPT-6.1 Sol 已进入 OpenAI API，主打接近 Astra 的复杂编码、computer use 和专业工作能力，同时成本更低。官方模型页显示标准价为输入 $2 / 百万 token、输出 $10 / 百万 token，支持最高 1.05M context。Work 与 Codex 正在分批 rollout；官方资料明确写着目前还没有进入普通 Chat。

为什么值得知道：它把“高端 Agent 能力”和“可承受的生产成本”拉得更近。

实用启发：选模型不要只看峰值能力；对真实任务同时测成功率、token、延迟和单次任务总成本。

2. OpenAI 推出 dots：长期运行的“always-on” Agent

9 月 29 日 · OpenAI 官方系统卡 + Reuters

发生了什么：OpenAI 在 Developer Day 推出 dots。官方系统卡称，每个 dot 有自己的云电脑和浏览器，可连接工具、处理重复工作，并通过 ChatGPT、短信、邮件和 Slack 跟进任务，还能把子任务交给 sub-agent。它由 GPT-6 Astra 驱动。官方已宣布/推出该产品，但不同账号的具体开放范围不应简单理解为“所有 Chat 用户都已 GA”。

为什么值得知道：Agent 正从“一次问答”变成会长期追踪目标的后台执行者。

实用启发：长期 Agent 必须设计权限过期、人工确认、审计日志和停止机制，不能只靠 prompt 约束。

3. Anthropic 发布 Claude Sonnet 5.5

9 月 28 日 · Anthropic 官方

发生了什么：Sonnet 5.5 已可在 Claude.ai 使用，也已进入 Claude API、AWS、Google Cloud 和 Microsoft Foundry。官方称生成速度比 Sonnet 5 快 30% 以上，典型任务总成本最高可低约 30%；API 标准价仍是输入 $2、输出 $10 / 百万 token。

为什么值得知道：它不是单纯“更强”，而是把速度、质量和成本一起优化，更适合高频工程任务。

实用启发：做编码 Agent 时，用自己的 bug 修复、repo 修改和长流程任务做 eval，别直接把厂商 benchmark 当生产结论。

4. NVIDIA 推出 Open Agent Safety Platform

9 月 28 日 · NVIDIA 官方

发生了什么：NVIDIA 发布 Open Agent Safety Platform：OpenShell 是开源安全运行时，把 Agent 放进隔离 sandbox，并限制文件、网络、工具和凭据访问；Sentry 则可在 BlueField-4 上做独立监控与干预。OpenShell 可扩展到第三方硬件，但 Sentry 的硬件监控方案不是“任何机器开箱即用”。

为什么值得知道：Agent 安全开始从应用层 guardrail 下沉到运行时和基础设施层。

实用启发：生产 Agent 的正确思路越来越像后端安全：最小权限 + sandbox + policy + 独立监控。

5. Anthropic：GLM-5.3 已具备强自主网络攻击能力

9 月 29 日 · Anthropic Research 官方

发生了什么：Anthropic 发布对 Z.ai GLM-5.3 的安全研究，称其已经能自主构建复杂的端到端 cyber exploits。这里是安全能力评估，不是 Anthropic 发布新模型，也不意味着所有真实攻击都能自动成功。

新手知识点

GA、rollout、preview 到底差在哪？

人话定义：“发布了”不等于“所有人都能用”。GA（Generally Available） 通常表示正式广泛可用；rollout 是分批开放；preview 是预览阶段，功能、配额或稳定性仍可能变化；allowlist 则只有被批准的账号能用。

短例子：GPT-6.1 Sol 已在 API 可用，但 Work/Codex 是分批 rollout，而普通 Chat 目前还没有开放——这三种状态可以同时成立。

什么时候有用：看模型新闻、做产品排期或向客户承诺功能时，先确认“在哪个产品、哪个地区、什么计划、是否 GA”。

工程师 / AI 产品视角

工程师视角

Agent 越能长期运行，越要把它当成“拿着权限的后台服务”：权限、sandbox、凭据、审计、超时和人工确认都要进入架构设计，而不是上线前最后补一个 guardrail。

AI 产品视角

未来的竞争点不只是“聊天更聪明”，而是用户是否愿意把连续任务交给 Agent。产品要让用户随时看见它正在做什么、为什么做、能否撤销，以及哪些动作必须先确认。
