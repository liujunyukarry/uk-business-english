3. Terminal-Bench-Science：最强系统在真实科研工作流上也只有 30%

8 月 28 日 · Terminal-Bench-Science v0.1

30 秒看懂：这个新 benchmark 用 70 个来自真实科研工作的终端任务测试 AI Agent。当前榜单里 Claude Opus 5 + Claude Code 的 resolution rate 为 30.0%，GPT-5.6 Sol + Codex 为 22.4%，Claude Fable 5 + Claude Code 为 21.4%。

为什么重要：它提醒你：今天很多“模型能力”其实是系统能力。模型、Harness、工具权限、上下文策略、推理强度和成本都会改变结果。因此这张榜不能直接解读成“Opus 5 本体一定比 GPT-5.6 Sol 强 7.6 个点”。
评测提示：这是“模型 + Agent/CLI Harness”的组合评测；不同系统使用的 token 数、工具和执行方式不同，因此适合比较具体系统在该任务集上的表现，不适合作为全能力总排名。

🧠 今日必懂 AI 概念

概念 1：Harness（Agent 执行框架）

一句人话
Harness 就是“让模型真正能干活的外骨骼”。模型负责想，Harness 负责把它接到文件、终端、浏览器、工具、记忆、权限和循环上。
举个例子
同一个模型放进普通聊天框，只能回答；放进 Codex、Claude Code 或 DeepSeek Harness，它就能读项目、改代码、跑测试、继续修错。
稍微技术一点
Harness 通常包含 agent loop、tool registry、context management、session/state、sandbox、approval/permission、compaction、subagents、logging/trajectory 等。
开发时何时碰到
只要你做“模型需要连续多步操作”的产品，就会碰到。比如自动改代码、自动分析公司文档并调用系统、自动执行 DevOps。
你只需记住
Agent ≠ 模型。 很多 Agent 产品差异，来自 Harness，而不是模型本身。

概念 2：MoE 与 Active Parameters

一句人话
MoE（Mixture of Experts）像一家有很多专家的大公司：总员工很多，但每个任务只叫一小部分专家来处理。
举个例子
2.4T-A95B 可以理解为“总共约 2.4 万亿参数，但一次 token 推理大约只激活 950 亿参数”。
稍微技术一点
路由器会为每个 token 选择部分 expert 子网络。这样模型可以拥有很大的总容量，但每次推理不必执行全部参数的计算。
开发时何时碰到
你在评估开源模型部署成本时，不能只看总参数。总参数更影响权重存储/显存，active parameters 更直接影响每 token 的计算量。
你只需记住
“总参数决定模型有多大；激活参数决定每一步实际动多少计算”——这是简化但非常实用的理解。

概念 3：Benchmark Protocol（评测协议）

一句人话
同一道考试，用不用计算器、能不能上网、给多少时间，都会改变分数；AI benchmark 也一样。
举个例子
Terminal-Bench-Science 比的是“模型 + Claude Code/Codex 等执行环境”，不是把模型裸放在那里答选择题。
稍微技术一点
关键变量包括：工具权限、系统提示、推理预算、上下文长度、是否多次尝试、agent loop、测试集污染、评分器和运行环境。
开发时何时碰到
选模型时。看到“模型 A 排名第一”，第一反应应该是：在哪个任务集？用什么 Harness？花了多少 token 和钱？
你只需记住
先看协议，再看分数。 不同协议下的数字不要直接横比。

🔍 模型名字拆解：Qwen3.8-2.4T-A95B-FP8

这个名字是真实存在的官方 Qwen 模型。你以后看到类似命名，可以按下面顺序拆。

Qwen3.8模型系列 / 世代。先把它理解为产品家族名。
2.4T总参数量约 2.4 trillion（2.4 万亿）。它是超大 MoE 模型，不意味着每生成一个 token 都会计算全部 2.4T 参数。
A95BActive 95B：一次前向计算大约激活 950 亿参数。A 就是 Active。这个数字比 2.4T 更接近“每 token 实际参与计算的规模”。
FP88 位浮点表示。相比 BF16/FP16，通常能显著降低权重显存和带宽压力，并提升支持 FP8 的服务器 GPU 上的推理效率；实际质量与速度取决于量化/实现和硬件。

那它能不能在我的电脑上跑？

官方 Hugging Face 仓库当前约 2.5 TB，明显不是普通笔记本/单张消费级显卡的本地模型。它更适合多 GPU 服务器或云端集群。官方页面给出了 vLLM 和 SGLang 的服务启动方式。

一个容易混淆的点：A95B 不代表只需要存 95B 参数。 MoE 推理时虽然只激活部分 expert，但完整权重仍需要被存储/分片，除非使用特殊 offload 或分层加载方案。

🛠 AI 工程实践：DeepSeek Harness 到底是什么？

成熟度：快速发展 / Developer Preview⚠ 不属于稳定生产标准

一句话：DeepSeek Harness 不是新模型，而是一套“把模型变成可执行 Agent”的开源运行时。DeepSeek 自己的公式就是：Agent = Model + Harness。

它解决什么问题？

如果你自己从零做 Agent，会发现麻烦的不是一次 LLM API 调用，而是：工具怎么注册、状态怎么保存、上下文怎么压缩、出错怎么继续、沙箱怎么隔离、多 Agent 怎么调度、运行过程怎么回放。Harness 就是把这些“Agent 基础设施”收拢起来。

DeepSeek Harness 有什么特别？

它主打 Everything is a plugin：模型、工具、skills、sessions、sandbox、storage、loop、scheduler、UI 都是插件。底层由 Cordis 管理插件挂载和依赖。它还把完整 trajectory 做成一等对象，方便 resume、fork、search、replay。

什么时候值得你试？

✓ 你想研究 Agent Harness 本身、尝试替换不同模型/工具/沙箱、研究 Agent 可观测性和轨迹回放。

✓ 你要做比较“重”的 coding agent / autonomous agent，而不是简单聊天机器人。

什么时候暂时别用？

如果你的产品只是“用户提问 → 查数据库/RAG → 调一次模型 → 返回结构化结果”，普通 workflow 往往更简单、更可控。DeepSeek 官方明确写着 Developer Preview，且存在 breaking changes；生产系统现在押死它风险较高。

快速判断：能用普通函数编排解决，就先别上 Agent；需要模型自己决定多步动作、反复观察环境并持续执行时，再考虑 Harness。

🏗 如果你以后设计 AI 产品，今天意味着什么

1. 把模型供应商做成 Adapter，而不是写死。
业务层最好面向统一接口：messages、tools、structured output、streaming、usage。OpenAI/Cursor 事件就是现实版“供应商依赖风险”。
2. 能用确定性 workflow，就不要为了“Agent 感”硬上 Agent。
支付、权限、数据库写入、合规流程等关键步骤应让传统代码掌控；模型负责判断、生成或推荐，代码负责最终约束。
3. 做 Agent 评测时，测“整个系统”，不要只测模型。
记录模型版本、Harness 版本、prompt、工具权限、token 成本、成功率和耗时。否则升级任何一层后，你都不知道性能为什么变化。
