修订不一致的API接口文档

Correcting Inconsistent API Documentation

每天十分钟学习真实英国职场场景中的实用口语。

今天的10句

前6句重点掌握，后4句自然表达；★为3句高频重点。

重点掌握 · 6句

1 ★ 高频重点

Does the example match the current API response?

/dʌz ði ɪɡˈzɑːmpəl mætʃ ðə ˈkʌrənt ˌeɪ piː ˈaɪ rɪˈspɒns/

文档示例和当前接口响应一致吗？

match＝内容一致；response＝接口返回数据。
2

No, the response has a new optional field.

/nəʊ ðə rɪˈspɒns hæz ə njuː ˈɒpʃənəl fiːld/

不一致，响应里多了一个可选字段。

optional field＝允许不存在的字段。
3 ★ 高频重点

Can we update the example without changing the API?

/kæn wiː ʌpˈdeɪt ði ɪɡˈzɑːmpəl wɪˈðaʊt ˈtʃeɪndʒɪŋ ði ˌeɪ piː ˈaɪ/

能只修改示例、不改动接口本身吗？

without changing＝在不修改另一部分的前提下。
4

Yes, this is a documentation correction only.

/jes ðɪs ɪz ə ˌdɒkjumenˈteɪʃən kəˈrekʃən ˈəʊnli/

可以，这次只是文档纠正。

correction＝修正已有错误。
5 ★ 高频重点

Should we explain what happens when the field is missing?

/ʃʊd wiː ɪkˈspleɪn wɒt ˈhæpənz wen ðə fiːld ɪz ˈmɪsɪŋ/

要不要解释这个字段缺失时会怎样？

missing field＝字段未返回，并非值为零。
6

Definitely. Clients need to handle that case.

/ˈdefɪnətli ˈklaɪənts niːd tə ˈhændl ðæt keɪs/

当然，客户端需要处理这种情况。

handle that case＝正确处理这一种情况。

自然表达 · 4句

7

The parameter description is too vague.

/ðə pəˈræmɪtə dɪˈskrɪpʃən ɪz tuː veɪɡ/

参数说明过于模糊。

vague＝不够具体，容易让人误解。
8

Let's include one valid request and one invalid request.

/lets ɪnˈkluːd wʌn ˈvælɪd rɪˈkwest ənd wʌn ɪnˈvælɪd rɪˈkwest/

加一个有效请求和一个无效请求的示例吧。

valid / invalid＝符合或不符合接口要求。
9

I'll ask the consumer team to review the wording.

/aɪl ɑːsk ðə kənˈsjuːmə tiːm tə rɪˈvjuː ðə ˈwɜːdɪŋ/

我会请接口使用方团队评审措辞。

consumer team＝调用该接口的团队。
10

We should publish the correction with the release notes.

/wiː ʃʊd ˈpʌblɪʃ ðə kəˈrekʃən wɪð ðə rɪˈliːs nəʊts/

应该把这项修正写进发布说明。

release notes＝发布版本时提供的变更说明。
