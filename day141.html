验证重复提交时的接口行为

Testing Duplicate API Submissions

十分钟学会真实英国职场场景中的自然口语。

今天的10句

前6句重点掌握，后4句自然表达；★标出3句高频重点。

重点掌握 · 6句

1 ★ 高频重点

What happens if a user submits the form twice?

/wɒt ˈhæpənz ɪf ə ˈjuːzə səbˈmɪts ðə fɔːm twaɪs/

如果用户重复提交表单，会发生什么？

submits twice＝同一操作执行了两次。
2

The service currently creates two separate records.

/ðə ˈsɜːvɪs ˈkʌrəntli kriˈeɪts tuː ˈseprət ˈrekɔːdz/

目前服务会创建两条不同记录。

separate records＝彼此独立的两条数据。
3 ★ 高频重点

Can we give each submission a unique request key?

/kæn wiː ɡɪv iːtʃ səbˈmɪʃən ə juːˈniːk rɪˈkwest kiː/

能给每次提交加一个唯一请求标识吗？

unique request key＝用来识别同一次业务请求的标识。
4

Yes, we can recognise retries using that key.

/jes wiː kən ˈrekəɡnaɪz ˌriːˈtraɪz ˈjuːzɪŋ ðæt kiː/

可以，借助这个标识就能认出重试请求。

recognise retries＝识别再次发送的同一请求。
5 ★ 高频重点

Should repeated requests return the same result?

/ʃʊd rɪˈpiːtɪd rɪˈkwests rɪˈtɜːn ðə seɪm rɪˈzʌlt/

重复请求应该返回相同结果吗？

repeated requests＝反复发送的请求。
6

For this operation, that would be safer.

/fə ðɪs ˌɒpəˈreɪʃən ðæt wʊd bi ˈseɪfə/

对这个操作来说，那样更安全。

would be safer＝委婉表达某种方案更稳妥。

自然表达 · 4句

7

We need to avoid charging customers twice.

/wiː niːd tə əˈvɔɪd ˈtʃɑːdʒɪŋ ˈkʌstəməz twaɪs/

需要避免向客户重复扣费。

charge customers＝向客户收取费用。
8

Let's test two requests arriving almost together.

/lets test tuː rɪˈkwests əˈraɪvɪŋ ˈɔːlməʊst təˈɡeðə/

测试两条几乎同时到达的请求吧。

almost together＝时间非常接近，模拟并发。
9

The key should expire after a reasonable period.

/ðə kiː ʃʊd ɪkˈspaɪər ˈɑːftər ə ˈriːzənəbl ˈpɪəriəd/

这个标识应该在合理时间后失效。

expire＝达到保留期限后失效。
10

I'll document the expected response for a retry.

/aɪl ˈdɒkjument ði ɪkˈspektɪd rɪˈspɒns fər ə ˌriːˈtraɪ/

我会记录重试时预期的返回结果。

expected response＝接口应返回的结果。
